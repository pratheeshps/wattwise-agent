# Sprint 6 — Production Readiness Foundation

**Status:** PostgreSQL, authentication and configurable PDF storage are implemented; full authenticated end-to-end verification and production rollout gates remain.  
**Branch:** `feature/analytics-first-dashboard`  
**Principles:** user-owned data, tenant-scoped reads/writes, private PDF objects, no secrets in source control.

## Decisions implemented

- PostgreSQL is the metadata store, accessed through Prisma ORM 7 and the PostgreSQL driver adapter.
- Better Auth provides email/password authentication. Email verification is required and passwords must be at least 12 characters.
- Every bill row is owned by a Better Auth user. Database uniqueness and indexes are scoped by user.
- PDF storage is configurable through `STORAGE_PROVIDER`:
  - `local` stores files under `LOCAL_STORAGE_DIR` (default `./storage/bills`). This is the default for local development.
  - `s3` uses AWS S3 or an S3-compatible service such as Cloudflare R2 or MinIO.
- Object keys are generated by the server and are user-scoped. The object key is not exposed in public bill API projections.
- The authenticated download endpoint verifies ownership before reading a local object or issuing a short-lived S3 signed URL.

## Required environment

See `.env.example`. All modes require PostgreSQL, Better Auth URL/secret and SMTP for account verification. Local storage requires no cloud credentials. S3 mode requires `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, and `S3_ENDPOINT` when using an S3-compatible endpoint such as R2.

Never expose storage credentials with a `NEXT_PUBLIC_` prefix.

## Local development

1. Set `STORAGE_PROVIDER=local`.
2. Set `LOCAL_STORAGE_DIR=./storage/bills` or choose an absolute path outside the repository.
3. Run `npm run db:generate` and `npm run db:migrate:deploy`.
4. Start with `npm run dev`.
5. Back up both PostgreSQL and the local storage directory. The storage directory is ignored by Git and is not automatically backed up.

## S3-compatible deployment

1. Provision a private bucket and a least-privilege access key.
2. Set `STORAGE_PROVIDER=s3` and the S3 environment variables in the hosting platform.
3. For Cloudflare R2, use region `auto` and the account-specific R2 S3 endpoint.
4. Keep bucket public access disabled.
5. Test upload, authenticated download, deletion and rollback before accepting real bills.

## Security and operational acceptance

- Unauthenticated requests to bill, preview, delete, download and analysis APIs must return 401.
- A user must never read, delete, or analyze another user's bill by guessing an ID.
- Database uniqueness is `(userId, sha256)`, not global across unrelated users.
- Bucket access is private; only short-lived signed downloads are used in S3 mode.
- Local downloads stream through an authenticated route and never expose filesystem paths.
- Enforce the existing 10 MB PDF limit and PDF signature check before object upload.
- Reject path traversal in storage keys.
- Do not log consumer numbers, PDF bytes, signed URLs, secrets, or storage credentials.
- Backups, restore drills, rate limits, email delivery, account recovery and monitoring are deployment gates.
